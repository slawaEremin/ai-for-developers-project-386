# Календарь звонков

Упрощённый сервис записи на звонок по мотивам Cal.com. Владелец создаёт типы
встреч, а гость выбирает свободное время и бронирует встречу.

## Сценарии

### Владелец

1. Я создаю тип встречи «Консультация»: указываю название, описание
   и длительность — 30 минут.
2. Сохраняю тип встречи. Он появляется в каталоге и становится доступен
   гостям для записи.
3. Гость выбирает свободное время и подтверждает бронирование.
4. Я открываю общий список предстоящих встреч и вижу новую запись:
   «Консультация», дата, время и длительность 30 минут.

### Гость

1. Я открываю сервис без регистрации и выбираю тип встречи «Консультация».
2. Вижу описание, длительность и календарь на ближайшие 14 дней.
3. Выбираю день и свободный слот, например 10:00–10:30, и подтверждаю запись.
4. Вижу подтверждение с датой и временем встречи. Запись появляется в списке
   владельца, а занятый интервал становится недоступен для других бронирований,
   включая встречи других типов.

## Обязательные функции

- Создание типов встреч с названием, описанием и длительностью.
- Каталог типов встреч для гостя.
- Календарь свободных слотов в скользящем окне из 14 календарных дней.
- Бронирование свободного слота выбранного типа встречи.
- Подтверждение успешной записи.
- Общий список предстоящих встреч всех типов для владельца.
- Защита от двойного бронирования и любых пересечений интервалов,
  в том числе для разных типов встреч и одновременных запросов.

## Ограничения приложения

- Владелец календаря один и задан заранее.
- Авторизация, регистрация и личные кабинеты отсутствуют.
- Интеграции с внешними календарями и уведомления не входят в проект.
- Окно записи охватывает 14 календарных дней и сдвигается с течением времени.
- Длительность слота совпадает с длительностью выбранного типа встречи.
- Частичные пересечения встреч запрещены. Следующая встреча может начинаться
  в момент окончания предыдущей.
- Начало окна записи (сегодня или завтра), часы работы владельца, часовой пояс
  и шаг доступных стартов нужно выбрать и зафиксировать в спецификации.
- Допустимо хранить данные в памяти процесса или в базе данных. Сохранение
  после перезапуска не является условием приёмки. Если будет выбрано хранение
  в памяти, перезапуск сбросит записи; это ограничение нужно явно указать
  в документации реализации.

## Технические требования

- API описывается контрактом TypeSpec. Из него генерируются OpenAPI-спецификация
  и клиентский SDK для фронтенда.
- Серверные типы, схемы проверки запросов и маршруты генерируются, если это
  поддерживает выбранный фреймворк. Если подходящего серверного генератора нет,
  сервер реализуется по контракту, а соответствие проверяется тестами.
- Приложение должно собираться в Docker-образ и запускаться в контейнере.

Источник требований: [первый шаг проекта Hexlet](https://ru.hexlet.io/projects/386/members/52904?step=1).

## Разработка

Каркас построен на структуре [ai-starter](https://github.com/slawaEremin/ai-starter). Бэкенд находится в `apps/backend`, фронтенд в `apps/frontend`, Dockerfile в `apps/infra`, контракт TypeSpec в `specs`.

Реализована главная страница с описанием сервиса, примером выбора времени и
объяснением трёх шагов записи. Кнопка «Записаться на звонок» ведёт на отдельную
страницу-заглушку с возвратом на главную. Описанные выше функции календаря
ещё не реализованы; обе страницы предупреждают, что онлайн-запись пока недоступна.

Нужны Git, GNU Make 3.81 или новее, [uv 0.13.7](https://docs.astral.sh/uv/getting-started/installation/), Node.js 24.22.2 и npm 10.8.2. Версия Node указана в `.nvmrc`, npm — в `packageManager` корневого `package.json`, uv — в `tool.uv.required-version` файла `apps/backend/pyproject.toml`. uv установит Python 3.13.18 из `apps/backend/.python-version`, если подходящей версии нет на компьютере. Первая установка требует доступа к сети.

Если используете nvm, выполните `nvm install` и `nvm use` из корня репозитория. Установите npm указанной в проекте версии, затем подготовьте зависимости и запустите проверки:

```sh
npm install --global "$(node --print "require('./package.json').packageManager")"
make setup
make check
```

| Команда | Действие |
| --- | --- |
| `make setup` | Установить зависимости из lock-файлов и сгенерировать контракт, модели и SDK |
| `make lint` | Проверить Python, Vue, TypeScript, TypeSpec и актуальность генерации |
| `make test` | Запустить тесты бэкенда и фронтенда без watch-режима |
| `make build` | Проверить типы и собрать фронтенд |
| `make check` | Последовательно выполнить `make lint`, `make test` и `make build`; остановиться при ошибке |
| `make generate` | Обновить OpenAPI JSON, модели Pydantic и TypeScript SDK |

Команды поддерживают `make -C /путь/к/репозиторию`. Зависимости закреплены в `apps/backend/uv.lock` и корневом `package-lock.json`. Команда `make setup` не добавляет Git-хуки и глобальные инструменты.

После подготовки окружения для всех проверок достаточно `make check`, в том числе при запуске с `-j`. Эта же команда выполняется в GitHub Actions на каждый push в любую ветку или тег. CI устанавливает зависимости из lock-файлов без `make setup`, чтобы не перезаписывать сгенерированные файлы до проверки их актуальности. Docker проверяется отдельно. Подробнее — в [описании workflow](.github/workflows/README.md).

[![Проверки проекта](https://github.com/slawaEremin/ai-for-developers-project-386/actions/workflows/check.yml/badge.svg)](https://github.com/slawaEremin/ai-for-developers-project-386/actions/workflows/check.yml)

Запустите приложения в отдельных терминалах.

```sh
cd apps/backend
uv run --locked uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

```sh
# Из корня репозитория
npm run dev --workspace apps/frontend
```

Главная страница Vue доступна по адресу `http://127.0.0.1:5173/`,
заглушка записи — по адресу `http://127.0.0.1:5173/#/booking`.
Обе страницы работают без обращения к API. Бэкенд отвечает на
`GET http://127.0.0.1:8000/health` JSON `{"status":"ok"}`.
Swagger UI доступен по адресу `http://127.0.0.1:8000/docs`.

Для сборки фронтенда выполните `npm run build`. Для сборки и запуска всего приложения в одном контейнере используйте Docker.

```sh
docker build -f apps/infra/Dockerfile -t calendar .
docker run --rm -p 8000:8000 calendar
```

В контейнере FastAPI отдаёт API и собранную страницу по адресу `http://127.0.0.1:8000/`. Подробности находятся в [README бэкенда](apps/backend/README.md), [README фронтенда](apps/frontend/README.md), [описании контракта](specs/README.md) и [инструкции Docker](apps/infra/README.md).
