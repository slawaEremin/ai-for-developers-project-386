# Фронтенд

Vue 3, TypeScript в строгом режиме и Vite. Нужны Node.js 24.22.2 из корневого `.nvmrc` и npm 10.8.2 из `packageManager` корневого `package.json`. Зависимости входят в корневой npm workspace и закреплены общим `package-lock.json`.

Из корня репозитория выполните `make setup`, затем запустите Vite.

```sh
npm run dev --workspace apps/frontend
```

Главная страница доступна по адресу `http://127.0.0.1:5173/`. Она рассказывает
о сервисе и ведёт к записи без регистрации. Общая шапка содержит ссылки
«Записаться» и «Админка». Главная использует градиентный фон; каталог
и запись — светлые карточки. Профиль «Владелец календаря» и нейтральный
аватар заданы во фронтенде, без отдельного API профиля.

Кнопки записи ведут на `http://127.0.0.1:5173/#/booking` — каталог типов
встреч из API. Каталог различает загрузку, пустой список и ошибку с явным
повтором. Каждая карточка целиком открывает отдельный экран записи,
скрывая каталог.
На нём показаны название, обычное текстовое описание и длительность встречи,
месячный календарь и свободное время. Кнопка «Назад» возвращает к каталогу
и очищает выбор.
Ссылка `/#/booking?type=consultation` восстанавливает выбранный тип, включая
перезагрузку с актуальными данными. Неизвестный тип показывает сообщение
и оставляет каталог доступным; ошибка чтения типа позволяет повторить запрос.
В адресе хранится только тип, без даты и слота. Календарь получает доступность
через сгенерированный SDK. Месячная сетка содержит 6 недель с понедельника;
даты вне 14-дневного окна отключены. Внутри окна видны количества свободных
слотов, а пустой день можно выбрать. Стрелки переключают только месяцы,
содержащие окно записи. Справа показаны только свободные интервалы из API
с шагом стартов 30 минут; список прокручивается отдельно от кнопок действий.
Изначально выбирается ближайшая свободная дата. Полные интервалы и даты с годом
отображаются по Europe/Moscow в 24-часовом формате независимо от часов устройства.
Загрузка, ошибка с повтором, пустой день и пустое окно различаются; во время
загрузки старые интервалы недоступны. Возвращение во вкладку и московская
полночь обновляют доступность по серверному времени: допустимая дата сохраняется,
вышедшая из окна заменяется ближайшей свободной, исчезнувший слот сбрасывается
с сообщением. Смена типа и обычная перезагрузка сбрасывают выбор даты/слота.
Выбор времени завершается отдельным подтверждением записи, описанным ниже.
Главная не требует API; каталогу нужны запущенные бэкенд и PostgreSQL.

Ссылка «Админка» открывает `/#/owner` без входа и регистрации. Форма
создаёт тип встречи через сгенерированный SDK и POST `/api/meeting-types`.
Обязательны id, название, описание и длительность 1–540 минут. Проверка
выполняется при отправке, ошибки обновляются при исправлении. Во время
запроса форма заблокирована; ошибка сохраняет ввод, успех очищает форму
и показывает ссылку на созданный тип. При потере ответа предлагается
проверить отправленный id по ссылке на каталог с выбранным типом;
автоматического повтора нет. Черновик после ухода со страницы не сохраняется.
Для формы нужны запущенные PostgreSQL и бэкенд; Vite проксирует `/api`
на `http://127.0.0.1:8000`. Интерфейс адаптирован для телефона от 320 px.
При ширине до 1024 px
карточки записи располагаются вертикально, до 760 px главная и каталог
переходят в одну колонку. При переходах фокус получает заголовок экрана
или шага подтверждения; доступны клавиатурная навигация и заметный фокус.

Для страниц используется навигация по hash без дополнительного роутера.
Такие ссылки можно открывать напрямую и перезагружать при раздаче файлов
через FastAPI без серверного перенаправления на `index.html`.
При смене страницы обновляются заголовок вкладки и фокус на заголовке страницы.

```sh
npm run lint --workspace apps/frontend
npm run test --workspace apps/frontend
npm run build
```

Тесты Vitest монтируют корневой компонент в DOM через Vue Test Utils и проверяют
описание сервиса, каталог и его состояния, прямые ссылки, форму владельца
и навигацию между страницами.
Линтинг включает ESLint и проверку типов `vue-tsc`. Сборка сохраняется в `apps/frontend/dist`.

Из корня репозитория доступны `make test` для тестов обоих приложений и `make build` для сборки фронтенда. Единая команда `make check` последовательно запускает линтинг, проверку генерации, тесты и сборку; она же выполняется в GitHub Actions на каждый push.

SDK в `src/api/generated` генерируется командой `make generate` и используется формой владельца и гостевым каталогом. Генерация SDK и установка зависимостей выполняются из корня репозитория.

Выбор слота обновляет сведения слева и разблокирует «Продолжить». Эта кнопка
открывает итог справа с типом, длительностью, датой и полным московским
интервалом; переход не отправляет POST и не сохраняет попытку. «Назад»
из итога возвращает к списку слотов с сохранённым выбором. Запись создаётся
только отдельной кнопкой «Подтвердить запись». Если слот исчез при обновлении
доступности, итог закрывается и выбор времени сбрасывается с сообщением.
Во время подтверждения выбор типа, даты и слота заблокирован. Успешный ответ
показывает подтверждение, «Выбрать другое время» очищает слот и обновляет
доступность. Конфликт сохраняет тип и дату, сбрасывает слот и обновляет календарь.
Технический или непонятный ответ показывает неизвестный результат; явный повтор
отправляет тот же ключ и исходные данные, выбор до определённого исхода закрыт.

Перед первым POST исходные UUID-ключ, тип и начало сохраняются в sessionStorage
текущей вкладки. При перезагрузке незавершённая попытка сразу отображается
с неизвестным результатом; POST запускается только кнопкой «Повторить
подтверждение». Новый адрес типа и обновлённое окно дат её не заменяют.
Ожидание ограничено 15 секундами: браузер прекращает ждать, сохраняет попытку
и блокирует новый выбор. Это не отменяет возможную запись на сервере.
Поздние ответы прежней отправки игнорируются. Сеть, 500, 503 и непонятный
ответ сохраняют попытку; успех и однозначный отказ её завершают. После успеха
обычная перезагрузка не восстанавливает подтверждение. Если сохранить попытку
не удалось, отправка недоступна. Закрытие вкладки не отменяет запись;
восстановление попытки после её закрытия не гарантируется, истории гостя нет.

## Список владельца и сквозная проверка

Рядом с формой на `/#/owner` показаны предстоящие встречи всех типов:
название, дата с годом, полный интервал в 24-часовом формате, длительность
и Москва (Europe/Moscow). Чтение списка использует сгенерированный SDK.
Загрузка выполняется при открытии, возвращении во вкладку/фокусе окна
и кнопкой «Обновить встречи», без периодического опроса. Начавшиеся встречи
исчезают при следующей загрузке. Пустое состояние отличается от ошибки;
ошибка обновления оставляет последний список с отметкой об устаревших данных
и кнопкой повтора. Загрузка и ошибка списка не блокируют форму и не меняют ввод.

Автоматический сценарий Playwright запускает настоящий Chromium: владелец
создаёт тип на 45 минут, гость по полученной ссылке выбирает и подтверждает
слот, владелец обновляет список и видит запись, в том числе после перезагрузки.
Браузер использует часовой пояс America/Los_Angeles для проверки московского
отображения. Запросы идут из приложения через SDK к настоящему FastAPI и PostgreSQL,
без подмены сети. Готовая production-сборка раздаётся тем же FastAPI.

Отдельный браузерный сценарий проверяет главную, каталог и запись при ширине
1400, 375 и 320 px: отсутствие горизонтального переполнения, выбор карточки
с клавиатуры, фокус заголовков, просмотр последнего слота и возврат из итога.
Снимки трёх экранов сохраняются в `apps/frontend/test-results` для визуальной
проверки.

Из корня после `make setup` и запуска PostgreSQL:

```sh
npx playwright install chromium
npm run test:e2e
```

При уже установленном Chrome доступен вариант без загрузки браузера:
`E2E_BROWSER_CHANNEL=chrome npm run test:e2e`. По умолчанию используется
закреплённый Playwright Chromium, в том числе в CI.

В Linux для системных библиотек: `npx playwright install --with-deps chromium`.
`npm run test:e2e` сначала собирает фронтенд, затем `scripts/e2e.py` создаёт
уникальную схему `calendar_e2e_<uuid>`, применяет настоящие миграции,
запускает отдельный сервер на свободном локальном порту и выполняет сценарий.
По завершении, включая неуспех браузера, сервер останавливается, удаляется только
схема этого прогона. `TEST_DATABASE_URL` выбирает сервер PostgreSQL
(по умолчанию `postgresql://calendar:calendar@127.0.0.1:55431/calendar`),
нужны права создания схем. `DATABASE_URL` приложения и данные `public`
не используются сценарием. Локальный dev-сервер останавливать не нужно.
При ошибке Playwright сохраняет трассировку в `apps/frontend/test-results`.
Сценарий также выполняется в `.github/workflows/check.yml` после `make check`.
