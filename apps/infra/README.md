# Инфраструктура

## Автономный образ

Контекст сборки и `Dockerfile` находятся в корне репозитория. Образ содержит
Python, PostgreSQL 17, бэкенд, собранный Vue и зависимости исполнения;
работает от непривилегированного пользователя `app`.

```sh
docker build -t calendar .
docker run -d --name calendar -e PORT=9000 -p 9000:9000 \
  -v calendar-standalone-data:/app/data calendar
```

Откройте `http://127.0.0.1:9000/`. Сервер запускается автоматически на
`0.0.0.0:$PORT`, по умолчанию порт `8000`. Допустимы целые числа от 1 до 65535;
некорректный `PORT` останавливает запуск до инициализации БД. В `-p` укажите
выбранный внутренний порт. `EXPOSE 8000` описывает только значение по умолчанию.

Команда `python -m app.container_start` всегда использует встроенную БД:
инициализирует кластер в `/app/data/pgdata` при первом запуске,
ждёт SQL-готовности не более 30 секунд
и создаёт отсутствующую БД `calendar` с пользователем `app`. PostgreSQL принимает
только локальные подключения через Unix-сокет в закрытом временном каталоге;
используется peer-аутентификация, TCP-порт БД не открывается. Затем выполняются
миграции, подготовка владельца и запуск одного процесса Uvicorn.

```sh
docker logs calendar
docker stop calendar
docker start calendar
# Пересоздание с сохранением календаря
docker stop calendar
docker rm calendar
docker run -d --name calendar -e PORT=9000 -p 9000:9000 \
  -v calendar-standalone-data:/app/data calendar
```

Том `/app/data` нужен для сохранения данных при удалении контейнера. Без тома
остановка и запуск того же контейнера сохраняют календарь, удаление — нет.
При остановке сначала завершается HTTP-сервер, затем PostgreSQL. Ошибка
подготовки или неожиданная остановка одного из процессов завершает контейнер
с ненулевым кодом; причины видны в `docker logs`.

Переданный контейнеру `DATABASE_URL` игнорируется. `OWNER_NAME` задаёт имя владельца
только при первом создании. Команда после имени образа переопределяет запуск:

```sh
docker run --rm calendar python --version
```

Сборка устанавливает закреплённые npm/Python зависимости, генерирует контракт,
модели и SDK, затем собирает Vue. PostgreSQL 17 устанавливается из официального
репозитория PGDG для Debian; кластер при сборке не создаётся.

Проверка собранного образа (нужен Docker Compose 2.24.4 или новее):

```sh
uv run --project apps/backend --locked python scripts/check_container.py calendar
```

Сценарий проверяет статику, бронирование, оба порта, остановку и перезапуск,
сохранность тома, отказы процессов, ошибки конфигурации и автономный Compose.
Он создаёт контейнеры, тома и сеть с уникальным префиксом `calendar-check-`
и удаляет только собственные ресурсы в конце.

## Автономный Compose

Docker Compose запускает один экземпляр FastAPI с одним рабочим процессом
Uvicorn, собранным Vue и встроенным PostgreSQL 17. Контекст сборки — корень.
Переменная `PORT` меняет порт сервера и публикацию; по умолчанию `8000`:
`PORT=9000 docker compose up --build -d`.

```sh
docker compose up --build -d
```

Главная: `http://127.0.0.1:8000/`, страница владельца:
`http://127.0.0.1:8000/#/owner`, запись гостя:
`http://127.0.0.1:8000/#/booking`, health: `http://127.0.0.1:8000/health`,
документация API: `http://127.0.0.1:8000/docs`.

После готовности PostgreSQL приложение выполняет отдельную команду
`python -m app.prepare`: применяет версионируемые миграции и создаёт заданного
владельца при отсутствии. Только успешная подготовка разрешает запуск сервера.
Причина ошибки видна в `docker compose logs app`. Проверка `/health` подтверждает
работу процесса; доступность БД проверяется операциями календарного API.

```sh
# Проверка сохранности после перезапуска
docker compose restart app
# Пересоздание контейнера с сохранением тома
docker compose up -d --force-recreate app
# Остановка с сохранением данных
docker compose down
```

Именованный том `calendar-standalone-data` хранит встроенную БД постоянно.
Не передавайте `--volumes` команде `down`, если данные нужны.

## БД для локальной разработки и тестов

Сервис `db` относится к профилю `development` и не запускается вместе с обычным
`docker compose up`. Он нужен бэкенду, который запускается локально вне образа.
Для разработки и автоматических проверок запустите БД отдельно;
явное указание сервиса активирует его профиль:

```sh
docker compose up -d db
make check
```

Учебные учётные данные `calendar` заданы в `compose.yaml`; эта БД публикуется
только на `127.0.0.1:55431` и хранится в прежнем томе `calendar-data`.
Том сохраняется, его данные автоматически не переносятся во встроенную БД.
Локальный `DATABASE_URL` и тестовый `TEST_DATABASE_URL` продолжают работать
(см. README бэкенда). Тесты используют изолированные временные схемы, не очищая
таблицы приложения.
