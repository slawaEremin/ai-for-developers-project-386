# Инфраструктура

Docker Compose запускает один экземпляр FastAPI с одним рабочим процессом
Uvicorn, собранным Vue и отдельным PostgreSQL 17. Контекст сборки — корень.

```sh
docker compose up --build -d
```

Главная: `http://127.0.0.1:8000/`, страница владельца:
`http://127.0.0.1:8000/#/owner`, гостевая заглушка:
`http://127.0.0.1:8000/#/booking`, health: `http://127.0.0.1:8000/health`,
документация API: `http://127.0.0.1:8000/docs`.

После готовности PostgreSQL приложение выполняет отдельную команду
`python -m app.prepare`: применяет версионируемые миграции и создаёт заданного
владельца при отсутствии. Только успешная подготовка разрешает запуск сервера.
Причина ошибки видна в `docker compose logs app`. Проверка `/health` подтверждает
работу процесса; доступность БД проверяется операциями календарного API.

```sh
# Повторная подготовка без очистки данных
docker compose run --rm app python -m app.prepare
# Проверка сохранности после перезапуска
docker compose restart db
docker compose up -d --wait db
docker compose restart app
# Пересоздание контейнера БД с сохранением тома
docker compose up -d --force-recreate db app
# Остановка с сохранением данных
docker compose down
```

Именованный том `calendar-data` хранит PostgreSQL постоянно. Не передавайте
`--volumes` команде `down`, если данные нужны. Учебные учётные данные `calendar`
заданы в `compose.yaml`; БД публикуется только на `127.0.0.1:55431` для разработки
и тестов. Конфигурация не предназначена для публичного размещения.

Для автоматических проверок достаточно запустить БД отдельно:

```sh
docker compose up -d db
make check
```

Тесты используют изолированные временные схемы, не очищая таблицы приложения.
Для другого сервера задайте `TEST_DATABASE_URL` (см. README бэкенда).

Сборка устанавливает закреплённые npm/Python зависимости, генерирует контракт,
модели и SDK, затем собирает Vue. Итоговый образ содержит Python, зависимости
исполнения, бэкенд и статику; работает от непривилегированного пользователя.
Для отдельной сборки: `docker build -f apps/infra/Dockerfile -t calendar .`.
Для отдельного запуска образа требуется `DATABASE_URL` доступного PostgreSQL;
сам образ БД не содержит.
